## 一、漏洞1：水平越权（IDOR）— 个人中心

### 1.1 漏洞信息

| 项目 | 内容 |
|:-----|:------|
| 漏洞名称 | 水平越权（Insecure Direct Object Reference） |
| 漏洞位置 | `/profile` 路由 |
| 风险等级 | 🔴 **严重** |
| CWE编号 | CWE-639: 通过用户控制键授权绕过 |
| 漏洞文件 | `app.py` line 241-276 |

### 1.2 漏洞描述

个人中心路由从 URL 参数 `user_id` 获取用户 ID 并查询资料，**未校验当前登录用户是否有权查看**。攻击者登录后只需修改 URL 中的 `user_id` 参数即可查看任意用户的资料。

### 1.3 攻击场景

```bash
# 正常访问自己的个人中心
GET /profile?user_id=1  → 显示 admin 的资料

# 越权攻击：查看其他用户的资料
GET /profile?user_id=2  → 显示 alice 的资料（越权成功 ✅）
GET /profile?user_id=3  → 显示其他注册用户的资料
GET /profile?user_id=99 → 尝试遍历所有用户
```

### 1.4 修复前代码（漏洞代码）

```python
@app.route("/profile")
def profile():
    username = session.get("username")
    if not username:
        return redirect(url_for("login"))

    # 🔴 漏洞：user_id 从 URL 参数获取，可被篡改
    user_id = request.args.get("user_id")

    # 🔴 漏洞：直接根据用户提供的 user_id 查询
    user = get_user_by_id(user_id)
    ...
```

### 1.5 修复后代码

```python
@app.route("/profile")
def profile():
    username = session.get("username")
    if not username:
        return redirect(url_for("login"))

    # ✅ 修复：从 session 获取当前用户
    user = get_user_by_username(username)
    user_id = user["id"]   # 从数据库查询当前用户ID

    # ✅ 修复：只能查自己的数据
    user = get_user_by_id(user_id)
    ...
```

### 1.6 修复措施

| 措施 | 说明 |
|:-----|:------|
| 数据来源变更 | `user_id` 从 URL 参数 → 从 session 获取用户名后查询数据库 |
| 权限校验 | 强制查询当前登录用户的资料，无法越权查看他人 |
| 移除入口 | 导航栏和首页的链接改为 `/profile`（不带参数） |

## 二、漏洞2：负值交易 — 充值功能

### 2.1 漏洞信息

| 项目 | 内容 |
|:-----|:------|
| 漏洞名称 | 负值交易（Negative Amount Transaction） |
| 漏洞位置 | `/recharge` 路由 |
| 风险等级 | 🟠 **高危** |
| CWE编号 | CWE-841: 业务逻辑错误处理 |
| 漏洞文件 | `app.py` line 283-314 |

### 2.2 漏洞描述

充值功能直接从表单获取 `amount` 参数，**未校验金额是否为正数**。攻击者可以传入负数来扣减任意用户的余额。

### 2.3 攻击场景

```bash
# 正常充值
POST /recharge
user_id=1&amount=100  → admin 余额 +100 元 ✅

# 负值攻击：给自己充负数（实际是扣钱）
POST /recharge
user_id=1&amount=-10000  → admin 余额 -10000 元 ✅ 漏洞利用成功

# 负值攻击：给任意用户扣钱（水平越权+负值组合）
POST /recharge
user_id=2&amount=-99999  → alice 余额被扣到负数 ✅
```

### 2.4 修复前代码（漏洞代码）

```python
@app.route("/recharge", methods=["POST"])
def recharge():
    # 🔴 漏洞：user_id 从表单参数获取
    user_id = request.form.get("user_id", "")
    amount = request.form.get("amount", "0")

    # 🔴 漏洞：未校验 amount 正负
    db.execute("UPDATE users SET balance = balance + ? WHERE id = ?", (amount, user_id))
```

### 2.5 修复后代码

```python
@app.route("/recharge", methods=["POST"])
def recharge():
    amount = request.form.get("amount", "0")

    # ✅ 修复：从 session 获取当前用户
    user = get_user_by_username(session.get("username"))

    # ✅ 修复：校验金额必须大于 0
    if amount <= 0:
        return render_template("profile.html", error="充值金额必须大于 0")

    # ✅ 修复：只能给自己充值
    db.execute("UPDATE users SET balance = balance + ? WHERE id = ?", (amount, user["id"]))
```

### 2.6 修复措施

| 措施 | 说明 |
|:-----|:------|
| 金额校验 | `amount <= 0` 时拒绝充值请求 |
| 用户来源 | `user_id` 从表单参数 → 从 session 获取（只能给自己充值） |
| HTML5校验 | 输入框增加 `min="0.01"` 属性，前端辅助校验 |
| 日志记录 | 拒绝负数充值时记录警告日志 |

## 三、修复前后对比总结

| 维度 | 修复前 | 修复后 |
|:-----|:-------|:-------|
| **/profile** | `?user_id=X` 可查任意用户 | 只能查自己的资料 |
| **/recharge** | 可给任意用户充值 | 只能给自己充值 |
| **/recharge amount** | 负数也可通过 | `amount > 0` 才允许 |
| **受影响的API** | 2个路由 | 0个（全部修复） |

## 四、防御建议

| 优先级 | 措施 | 说明 |
|:------:|:-----|:------|
| 🔴 必做 | 使用Session获取用户身份 | 所有敏感操作都从 session 获取当前用户 |
| 🔴 必做 | 金额正负校验 | 所有涉及金额的操作必须校验正负 |
| 🟠 建议 | 权限中间件 | 统一拦截越权请求 |
| 🟠 建议 | 操作日志 | 记录所有敏感操作便于追溯 |
| 🟡 可选 | 二次确认 | 大额充值增加确认弹窗或验证码 |
| 🟡 可选 | 金额上限 | 单次充值设置上限（如 99999） |
